# Интерфейс диспетчера — работа Константина

Реализованы русский интерфейс, импорт CSV/JSON, расчёт маршрутов, исключение
нескольких машин, сравнение планов, AI-команда с подтверждением, обработка ошибок,
цветные маршруты, номера остановок и неназначенные заказы на карте.

## Запуск

Из `frontend` в PowerShell:

```powershell
npm.cmd ci
npm.cmd run dev
```

Backend должен быть запущен по корневому README на `127.0.0.1:8000`.
Открыть адрес Vite, обычно `http://localhost:5173`.
Vite перенаправляет `/api/*` на backend; в production нужен аналогичный reverse
proxy либо `VITE_API_BASE_URL`, заданный перед сборкой. Для другого origin сервер
должен разрешать CORS. В frontend не нужны ключи AI-провайдера.

```powershell
npm.cmd test
npm.cmd run build
```

Новые runtime-зависимости не добавлены. В приложении нет демонстрационной
подмены серверных ответов: mock-ответы используются только в тестах.

## Передача Максиму и Нетесову

Frontend использует контракт `docs/team/00_Общий_план.txt`:

| Действие | Запрос | Ожидаемый результат |
| --- | --- | --- |
| Исключение машин | `POST /replans`, `{base_plan_id, unavailable_vehicle_ids}` | `ReplanResult` из `src/api/types.ts` |
| Разбор команды | `POST /agent/interpret`, `{message, base_plan_id}` | `AgentResult` из `src/api/types.ts` |

При повторном исключении передаётся текущий отображаемый план и полный список
исключённых в сценарии машин. `comparison` показывает переход от этого плана к
новому. После импорта, обновления dashboard или обычного расчёта сценарий
сбрасывается. Пересчёт сам по себе не меняет постоянные статусы машин.

`ready` показывает распознанные ID и кнопку подтверждения; `needs_clarification`
показывает вопрос; `unsupported` объясняет отказ. Ошибка AI не блокирует ручной
сценарий. Новые данные, пересчёт и редактирование команды отменяют применимость
старого AI-ответа, включая ответ ещё выполняющегося запроса.

Ошибки HTTP: `404 Not Found` — функция ещё не подключена, `409` — обновить план,
`422` — детали валидации, `503` для AI — ручное действие остаётся доступным.
Ожидание запроса ограничено 60 секундами; повторный клик не отправляет второй
запрос на изменение плана. После ошибки предыдущий успешный план сохраняется.
Если импорт принят, а обновить dashboard не удалось, старый план скрывается:
он уже не соответствует данным, нужно нажать «Обновить данные».

Семантика текущего backend: ETA включает обслуживание текущей остановки.
Время в сводке — сумма длительностей маршрутов. Меньшее расстояние при меньшем
числе доставок не обозначается как улучшение.

## Проверенный результат

21.09.2026:

- Production-сборка TypeScript/Vite проходит.
- Компонентные тесты проверяют ручной и AI-сценарии, частичный импорт, ошибки,
  блокировку повторных запросов, старые AI-ответы, карту и сравнение.
- В настоящем Chrome с существующим backend проверены загрузка dashboard,
  расчёт и чтение плана, частичный CSV-импорт, отображение ошибок отсутствующих
  endpoint и сохранение доступности ручных элементов управления.
- Проверены размеры 1366×768 и 390×844: горизонтального переполнения страницы нет,
  необработанных JavaScript-исключений в браузере нет.

На момент проверки backend ещё НЕ содержит `/replans` и `/agent/interpret`.
Успешные новые сценарии проверены автоматическими тестами по контракту;
сквозная проверка их с настоящим backend остаётся после реализации Максима
и Нетесова. Реальный AI-вызов frontend самостоятельно не выполняет.

## Сценарий общей проверки после подключения backend

1. Загрузить согласованные файлы машин и заказов. Проверить сводку и карту.
2. Нажать «Рассчитать маршруты», запомнить ID и показатели плана.
3. Выбрать машину, нажать «Исключить и пересчитать». Проверить новый ID,
   число доставок, причины неназначения, показатели «Было / Стало / Изменение».
4. Рассчитать исходный план заново. Выбрать пример команды с существующим ID,
   нажать «Разобрать команду», затем «Применить и пересчитать».
5. Отправить неоднозначную команду: должен появиться вопрос без пересчёта.
6. Получить AI-предложение и импортировать новые данные: старую команду применить
   нельзя. Проверить исключение всех машин и пустой список маршрутов.
7. Отключить AI-провайдер: ошибка понятна, ручной пересчёт работает.
8. Проверить demo-набор на ноутбуке выступающего и повторить финальную сборку.

Карта загружает подложку из OpenStreetMap. Если тайлы недоступны, появляется
сообщение; карточки маршрутов и таблицы продолжают работать. Линии на карте
соединяют координаты напрямую, GPS и дорожного routing пока нет.
