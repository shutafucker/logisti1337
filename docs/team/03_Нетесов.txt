НЕТЕСОВ — AI-МОДУЛЬ, ДЕМО-ДАННЫЕ, ЗАПУСК И ПРЕЗЕНТАЦИЯ

Твоя цель: AI выполняет полезную ограниченную функцию, а команда может доказать
работу решения на воспроизводимом сценарии. Сначала прочитай 00_Общий_план.txt.
Это подготовительный сценарий, а не заранее известное задание хакатона.

1. ТВОЯ ОБЛАСТЬ
Новые backend/app/agent/* и backend/tests/test_agent*.py.
demo/*, scripts/*, docs/demo/*, README.md, корневой .gitignore.
Ветка: feature/netesov-agent-demo.
main.py, schemas.py и pyproject.toml меняет Максим; frontend — Константин.
Нужные зависимости и подключение router передаёшь Максиму отдельным запросом.

2. СТЕК И РЕСУРСЫ
Python, Pydantic, FastAPI APIRouter, pytest; серверный клиент доступной AI-модели.
Модель и способ доступа выбрать после проверки реально выданных ресурсов.
SDK, поддерживаемый формат структурированного ответа и параметры запросов
проверить по актуальной официальной документации перед реализацией.
Не выбирать сложный агентный фреймворк для одного действия без необходимости.
Демо: CSV/JSON, PowerShell-скрипты запуска, Markdown для сценария выступления.
Для работы нужны: серверный API-ключ, доступная модель, интернет, данные с ID машин.
Секреты передавать через окружение. В .env.example — только имена и пустые значения.
Названия новых настроек предварительно согласовать: AI_API_KEY, AI_MODEL,
AI_TIMEOUT_SECONDS. Само добавление .env не загружает его в Python автоматически:
README должен описывать действующий способ настройки.

4. ЭТАП Б — AI-ИНТЕРПРЕТАТОР, P0
Рекомендуемое разделение:
backend/app/agent/schemas.py — локальные схемы AI-запроса/ответа.
backend/app/agent/service.py — интерпретация сообщения и проверка результата.
backend/app/agent/provider.py — изолированный вызов модели и настройки.
backend/app/agent/router.py — HTTP-адаптер с экспортом router.
Не импортировать app.main из модуля; не создавать отдельную постоянную БД.

[ ] Согласовать context с Максимом: текущий plan_id и список реальных ID машин.
[ ] Реализовать одно действие exclude_vehicles по контракту общего файла.
[ ] Передавать модели сообщение, разрешённое действие и минимальный контекст.
[ ] Требовать структурированный результат и валидировать его Pydantic.
[ ] Проверять ID по фактическому списку, а не доверять названию от модели.
[ ] Для «вторая машина» без однозначного соответствия возвращать уточнение.
[ ] Для неизвестного действия возвращать unsupported.
[ ] Не генерировать километры, ETA и назначения силами модели.
[ ] Ограничить размер сообщения, время ожидания и число повторов вызова.
[ ] При таймауте/нет ключа/ошибке провайдера возвращать понятную ошибку.
[ ] Не логировать ключи; не отдавать внутренний ответ провайдера целиком в UI.

Результат: реальный вызов модели превращает текст в допустимое действие.
Интерпретация сама не меняет план; пересчёт происходит через проверенный /replans.

5. ЭТАП В — ТЕСТЫ И ИНТЕГРАЦИЯ
Автоматические тесты использовать с подменённым провайдером без расходов API:
[ ] «VAN-02 сломалась» → ready с существующим ID.
[ ] «Машина сломалась» → needs_clarification.
[ ] Неизвестный ID не превращается в действие.
[ ] Запрос неподдерживаемого действия → unsupported.
[ ] Невалидный JSON/неправильная схема модели → управляемая ошибка.
[ ] Таймаут/отсутствие ключа не ломают запуск всего приложения.
[ ] Просьба игнорировать правила не разрешает произвольное действие.
Отдельно провести хотя бы один настоящий вызов модели и записать факт проверки,
название настроенной модели и дату без секретов. Mock-тест не доказывает живой API.
Передать Максиму router и инструкцию подключения; Константину — примеры всех
статусов. Вместе пройти сообщение → действие → пересчёт → сравнение.

7. ЭТАП Д — ДОКАЗАТЕЛЬСТВА И ПРЕЗЕНТАЦИЯ
Создать docs/demo/demo-script.md и docs/demo/results.md.
Сценарий выступления примерно на 3 минуты, адаптировать под регламент:
1) 20–30 секунд: кто пользователь и какая конкретная проблема из задания.
2) 30 секунд: входные данные и исходный план.
3) 60 секунд: событие/команда AI и построение нового плана.
4) 30 секунд: before/after, неназначенные заказы, соблюдение ограничений.
5) 30 секунд: роль AI, проверяемые расчёты, ограничения и дальнейшее применение.
Зафиксировать фактические числа, размер набора, настройки скорости/обслуживания.
Не писать «экономим 30%», если это не получено сравнением на одинаковых условиях.
При исключении машины результат может ухудшиться: ценность — увидеть последствия
и получить выполнимый план. Не скрывать неназначенные заказы.
Короткая резервная запись/скриншоты допустимы как запись, не как имитация live-демо.
Реальные критерии задания сопоставить с конкретными действиями в демонстрации.
