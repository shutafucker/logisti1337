КОНСТАНТИН — ИНТЕРФЕЙС, КАРТА И ДЕМОНСТРАЦИЯ РЕЗУЛЬТАТА

Твоя цель: пользователь проходит понятный путь от входных данных до нового плана
и видит последствия изменения. Сначала прочитай 00_Общий_план.txt.
Сценарий с поломкой машины — подготовительный, после задания его можно заменить.

1. ТВОЯ ОБЛАСТЬ
Весь frontend/: компоненты, API-клиент, типы, стили, тесты, настройки и зависимости.
Ветка: feature/konstantin-ui.
Не редактируешь backend. Новые поля API согласовываешь с Максимом.
Нетесов передаёт демо-данные и форматы AI-ответов, ты подключаешь их к экрану.

2. СТЕК И РЕСУРСЫ
React 19, TypeScript, Vite, Leaflet/react-leaflet, Vitest, Testing Library.
Сначала использовать существующие стили и компоненты, без замены UI-стека.
В PowerShell из корня проекта:
  cd frontend
  node --version
  npm install
  npm test
  npm run build
  npm run dev
Если в репозитории есть согласованный актуальный package-lock.json, для чистой
установки использовать npm ci. Изменения зависимостей коммитить вместе с lock-файлом.
API должен работать на порту 8000; Vite использует существующий proxy /api.
Прочитать src/components/Dashboard.tsx, MapPanel.tsx, src/api/client.ts и types.ts.

7. ПРОВЕРКИ
[ ] Импорт корректного файла обновляет данные и план.
[ ] Ошибочная строка импорта отображается с причиной; валидные строки не теряются.
[ ] Выбор машины → /replans → новый маршрут и обновлённая сводка.
[ ] Исходный и новый планы не перепутаны в сравнении.
[ ] Ошибка API не оставляет кнопку навсегда заблокированной.
[ ] AI-уточнение не запускает пересчёт.
[ ] Старый AI-ответ не применяется к новому набору данных.
[ ] Все машины исключены: понятное пустое состояние, список неназначенных заказов.
Расширить существующие компонентные тесты на эти переходы, где это существенно.
Не тратить время на тесты декоративных классов и каждой подписи.
Перед передачей: npm test и npm run build; затем ручной сценарий с реальным API.

8. ЧТО ПЕРЕДАТЬ КОМАНДЕ
Максиму: точные запросы/ошибки с шагами воспроизведения, без ключей и лишних логов.
Нетесову: последовательность кликов для демо, состояния экрана, готовые подписи.
В PR: какие действия работают, проверки, оставшиеся ограничения.
Первый PR — рабочая ручная цепочка. Второй — AI-панель. Оформление — после P0.

10. ГОТОВО, КОГДА
Человек без знакомства с кодом может загрузить сценарий, построить план,
исключить машину вручную или через AI и понять изменения. Проверки и сборка
проходят; демо работает с настоящим сервером; никаких обещаний live GPS.
